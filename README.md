# AI 模拟患者诊断教学平台（三端一体 Web 应用）

一个**纯前端、零构建**的医学诊断教学平台，包含三个端口：

- 🎓 **学生端**：与模拟患者对话问诊、历史记录与知识点总结、题库练习与积分。
- 🛠 **管理端**：API Key 与运行控制、AI 参数、资源白名单、提示词、题库、病例审核、数据总览。
- 🏥 **医院端**：对话式病例上传（文本 / PDF / 图片）、自动去隐私化结构化、病例管理。

技术栈：**原生 HTML5 + CSS3 + ES6**，不使用任何框架或构建工具。所有 JS 通过 `<script src>` 顺序加载、挂在全局 `window.App` 命名空间（**未使用 ES Module**，兼容 `file://` 双击打开）。数据持久化使用 `localStorage`（统一前缀 `aips_`）。

## 一、打开方式

1. 直接**双击 `D:\code\cursor\index.html`** 即可在浏览器中运行（推荐 Chrome / Edge / Firefox）。
2. 如需让 **Web Crypto（AES-GCM）真正生效**（更强的 Key 加密），建议用本地服务器打开：
   ```bash
   # 任选其一
   cd D:\code\cursor
   python -m http.server 8080      # 然后访问 http://localhost:8080
   # 或 npx serve .
   ```
   > 说明：浏览器在 `file://` 下通常不认为属于「安全上下文」，`window.crypto.subtle` 可能不可用。
   > 此时平台会自动降级为**异或混淆**存储 Key（仅防随手查看，非真加密），并在管理端给出提示。
   > 用 `http://localhost` 打开即可获得完整 AES-GCM 保护。

## 二、默认账号与初始数据

本平台为**本地单人演示**，没有登录账号体系，三端通过首页卡片直接进入：

- 首页 `#/portal`：三端入口。
- 首次运行会自动写入 **3 个示例病例**（急性心肌梗死、社区获得性肺炎、2 型糖尿病），每个病例附带 **4 道选择题 + 1 道简答题**，开箱即可演示。

### 演示模式（Mock Mode）

- **未配置 API Key 时自动进入演示模式**，顶部显示「🧪 当前为演示模式」横幅。
- 演示模式使用内置规则化「患者」引擎（关键词匹配 + 人设话术）、规则化结构化 / 出题 / 评分，**无需任何后端或网络即可完整走通全流程**。
- 配置真实 Key 后，所有 AI 交互自动切换为真实大模型（OpenAI 兼容接口）。

## 三、配置真实大模型（管理端）

进入 **管理端 → API 与运行**：

1. 填写 **API Key**（密码型输入，默认掩码，👁 可短暂查看已保存的 Key；复制按钮自动打码）。
2. 填写 **Base URL**（默认 `https://api.openai.com/v1`）与 **模型名称**（如 `gpt-4o-mini`）。
3. 点击「**保存并启用**」：Key 经 Web Crypto（AES-GCM）加密后写入 `localStorage`，全局开关置 `on`。
4. 「**立即抹除 Key**」：清空 Key 并停止全部 AI 调用。
5. 「**暂停 / 恢复 API 调用**」：全局总开关。关闭后，学生端聊天区、医院端上传区会显示「系统维护中，AI 服务已暂停」，所有请求被拦截。

状态指示灯：🟢 运行中 / 🔴 已停止 / 🟡 未配置（顶栏右上角）。

> ⚠️ **Key 保护**：Key 仅在解密后的内存闭包中短暂存在，页面切换即清空；`localStorage` 中均为密文；日志、报错、Toast、URL 中均不含 Key 明文；学生端 / 医院端 JS 不直接持有 Key 变量。

## 六、纯前端安全边界声明（重要）

本方案为**前端单机演示**，存在固有限制，正式接入真实医院数据前**必须升级架构**：

1. **API Key 不应出现在任何前端代码中**。当前 Key 仅做前端加密存储并尽力避免泄露，但前端代码对用户可见，**无法达到后端同等级别的安全**。
2. **务必改为「前端 → 自家后端代理 → LLM」转发**：前端把对话内容发给你的后端，后端持有 Key 并调用大模型，再把结果回传。这样 Key 不进浏览器，也能做鉴权、限流、审计与日志脱敏。
3. **后端代理接口约定（建议）**——前端向后端 `/api/llm/chat` 发请求：
   - **入参（前端 → 后端）**
     ```json
     { "messages": [ { "role": "system|user|assistant", "content": "..." } ],
       "model": "gpt-4o-mini", "temperature": 0.7, "top_p": 1,
       "max_tokens": 1000, "stream": true }
     ```
   - **出参（后端 → 前端）**
     - 非流式：`{ "choices": [ { "message": { "role": "assistant", "content": "..." } } ], "usage": { "total_tokens": 123 } }`
     - 流式（SSE，`text/event-stream`）：逐行 `data: {"choices":[{"delta":{"content":"..."}}]}` ，结束行 `data: [DONE]`
   - 后端负责：注入并保护系统提示词、校验用户权限、限流、对日志中的敏感字段脱敏。
4. **去隐私化**应在可信环境（后端或人工）完成；演示版前端的自动脱敏仅作辅助，**不能保证 100% 剔除隐私字段**，正式流程需人工复核。
5. `file://` 下 Web Crypto 可能不可用；生产/教学正式环境请部署到 HTTPS 或 localhost。

## 七、浏览器内验证步骤（无 Key 演示模式）

1. 双击 `index.html`（或 `http://localhost:8080`）。
2. 首页点击 **🎓 学生端 → 诊断对话 → 开始诊断**，选「胸痛 3 小时的退休工人」。
3. 输入「能说说您哪里不舒服吗？」→ 患者回复应含可点击的 `[[胸痛]]` 标签；点标签弹出临床信息。
4. 输入「您觉得自己得的是什么病？」→ 患者应**拒绝泄题**。
5. 多问几个维度（现病史 / 既往史 / 查体 / 检查），留意顶栏积分飘字与「关键线索 2/5」进度。
6. 点「结束诊断」，填写最终诊断「急性下壁心肌梗死」与依据 → 生成问诊报告（含线索发现率、人文评分、积分变动）。
7. 学生端 → 历史记录：查看刚才的对话回放与报告。
8. 学生端 → 题库练习：选该病例，作答 4 选择 + 1 简答，查看解析与积分。
9. 医院端 → 病例上传：粘贴一段病历文本，点发送 → 查看去隐私化结构化结果与脱敏清单 → 提交到平台。
10. 管理端 → 病例审核：应能看到刚提交的待审核病例，可发布 / 驳回。
11. 管理端 → 数据总览：各统计卡片有数据。
12. 管理端 → API 与运行：填写 Key 与模型，保存并启用 → 顶栏状态灯变 🟢；点「暂停」→ 学生端聊天区显示维护提示。

## 九、常见问题

- **双击打开后控制台报错？** 多为浏览器对 `file://` 的限制。请用 Chrome/Edge，或改用 `localhost` 本地服务器。
- **演示模式出题/评分较简单？** 演示用规则引擎生成；配置真实 Key 后由大模型生成更高质量的题目与评分。
- **积分不对？** 积分规则集中在 `js/score.js` 顶部的 `SCORE_RULES`，可按教学需要直接修改。
- **想加新病例？** 医院端上传并发布，或管理端可直接编辑 / 题库中增删题目。
